## 1. 背景

页面在 `/p/0c3751ac2af7`（不公开，见第 5 节），2026-10-31 上线，当时只有 67 条手工整理的价格。

数据 AI 当天就抓回了 **5,749 条**（`points/` 下 4 个文件：OzBargain 黑五 2,530、OzBargain 节礼日 2,547、Dealmoon 605、curated 67）。用这些数据本地构建后，页面基本不能用：

| 问题 | 实测（本地构建，5,749 条） |
|---|---|
| 页面太大 | HTML **1.6 MB**，923 个 SVG 圆点，916 个链接 |
| 散点图糊成一片 | 数码电子、其他两行几百个点叠在一起，看不出分布 |
| 异常值排第一 | “逐条折扣”第一名是 `iPhone 16e 128GB · Optus · $13.86（原价 $998.64）99%`——这是合约月费，不是折扣 |
| 噪音太多 | “其他”1,883 条（酒、燃油添加剂、圆珠笔）挤占版面；OzBargain 票数中位数只有 12–14，大部分是没人关注的帖子 |
| 对比结果错 | “黑五 vs 节礼日”出现 `Call of Duty: Black Ops 7：黑五 $69（2025）vs 节礼日 $15（2018-12-24）→ 等节礼日省 78%`。同一个 key 里混了 Black Ops 6、7、III，而且拿 2025 年黑五和 2018 年节礼日比 |
| 头部数字跳变 | 中位折扣 38% → 41%（269 条），最低价不在黑五 10/16 → 74/163。数字本身可以变，但现在没法看出是哪个来源、哪些异常值推动的 |

**目标**：数据涨到 1 万条时页面依然轻、准、好用，能直接回答 4 个问题——往年什么值得买、黑五是不是最便宜、该不该等节礼日、今年到多少钱下手。

## 3. 需求

### P0 — 11/10 前上线（11/12 起早鸟闪购就开始了）

**P0-1 页面瘦身**
- 不再把所有行都渲染进 HTML。每个列表默认只出前 N 条（建议 20），其余用“展开更多”或分页。
- 预算：**5,749 条数据时页面 HTML ≤ 400 KB**；数据翻倍时不超过 600 KB。
- 需要交互的部分做成小的客户端组件，**服务端先聚合好**，只把要显示的行传给客户端，不要把整个 points 数组塞给浏览器。

**P0-2 异常值和噪音**
- 折扣计算排除：`conditions` 非空的行（合约、会员、二手等）、折扣 > 90%、价格 < $5。页面上写明“已排除 n 条异常”，点开能看是哪些。
- “其他”品类默认隐藏（可以打开）。
- OzBargain 数据加“最低票数”门槛，默认 ≥ 20 票（可调）。其他来源 `votes` 为 null 的不受这个门槛影响。

**P0-3 对比逻辑改成同一季比**（`lib/bf2026.ts`）
- **黑五是不是最便宜**：黑五季年份 Y 的最低价，只和“购物年 Y”里的非黑五价比。购物年 Y = **Y-06-01 到 (Y+1)-05-31**，覆盖当年 EOFY、Prime Day、Click Frenzy、黑五、节礼日。
- **黑五 vs 节礼日**：黑五季 Y 只和节礼日季 Y 比（节礼日季用现有的 `seasonYear`，1 月算上一年）。
- 两边都只用 `conditions === ''` 的价，和提醒价同一规则；带条件的价可以在明细里显示，但不进结论。
- 每个结论旁边写样本量（n），样本 < 5 的品类不出中位数，只写“样本不足”。
- `forecast`（提醒价）规则不变。

**P0-4 筛选器**（一行放在图表上方）
- 品类（多选）、年份、来源文件、最低票数、是否显示“其他”。
- 筛选只影响“往年”和“对比”两块；头部数字卡显示的是**未筛选**的全量结论，并注明口径。
- 状态放 URL query（方便我收藏），不要用 localStorage。

**P0-5 品类折扣图换形式**
- 散点图在几百个点时不可读。改成每个品类一行的**分箱直方图**（5% 一格）或箱线图，黑五和节礼日上下并排或叠加（实心/空心或两种明度），中位数线保留。
- 横轴到 90%；超出范围的不能堆在边上。
- 图例、标签规则不变：颜色按品类固定顺序，文字用正文颜色。

**P0-6 “逐条折扣”改成“往年好价榜”**
- 每个品类前 20 条，排序：有票数的按票数，否则按折扣。
- 每行：商品、年份、商家、到手价、原价、折扣、票数、来源链接。
- 支持按品类切换（用 P0-4 的筛选器）。

### P1 — 11/20 前

**P1-1 上架节奏图**（素材见 `BF2026_TIMING.md`）
- 横轴：距黑五的天数（−21 到 +5），纵轴：当天新出的单品好价数量，按年份分线或小多图。节礼日同理（12/20 到 1/15）。
- 回答“哪天开始盯”。标出票数 ≥ 50 的好价各集中在哪几天。

**P1-2 关注清单卡片加明细**
- 每张卡显示这个 key 在所有来源里的点数和最近一次价格。
- 点开（`<details>` 就够）列出这个 key 的全部价格点：日期、活动、价格、条件、来源链接。

**P1-3 搜索**
- 搜商品名，在全部价格点里找。
- 数据不要塞进 HTML：在隐藏路径下生成一个构建期静态 JSON（例如 `app/p/0c3751ac2af7/search/route.ts`，`dynamic = 'force-static'`），只放搜索需要的字段，用户输入时再取。
- 这个 JSON 也是隐藏的：不进 sitemap、不在别处链接。

**P1-4 “怎么买最便宜”**
- 技巧卡片：打折礼品卡叠加、Officeworks 比价再便宜 5%、返现平台。素材见 `BF2026_XHS_FINDINGS.md` 第 2、8 节。
- 链到站内已有攻略：`/guides/discounted-giftcard-price-match-stack-au`、`/guides/buy-apple-products-au`、`/guides/shopback-receipt-scanning-au`（隐藏页链到公开页可以，**反过来不行**）。

**P1-5 返现和礼品卡活动**
- `promos/*.json` 有数据后，按年份画时间轴：哪家、什么活动、几号到几号。没数据时显示“等数据”。

### P2 — 有空再做

- “送谁”视图：按 `watch.json` 的 `who` 分组（国内亲友 / 伴侣家人 / Secret Santa），加上对应品类的往年好价。
- 数据覆盖改成热力图：来源 × 年份、关注商品 × 指标。
- 页面 `<head>` 不再继承首页的 canonical 和英文 og/description（noindex 下无害，但不整洁）。
- 黑五侧的标签把原始备注放进悬停提示（例如“卖家可能是水货”“来源为赞助文章”）。

## 5. 硬约束

1. **隐藏页**：
   - 路径不变（`/p/0c3751ac2af7`）；
   - 保持 `robots: { index: false, follow: false }`；
   - 不进导航、sitemap、robots.txt（写进 robots.txt 反而暴露）；
   - 这个随机码只允许出现在本页（及 P1-3 的数据路由）的路径里。
2. **静态**：构建时生成，`next build` 输出里是 `○`；`npx @cloudflare/next-on-pages` 必须通过。不要运行时读文件。
3. **Next.js 版本特殊**：先读 `frontend/AGENTS.md` 和 `frontend/node_modules/next/dist/docs/` 里相关章节，再写代码。
4. **一个坏数据文件不能拖垮全站部署**：现有 loader 的 `errors` 机制保留，页面顶部的警告框保留。
5. **手机**：375px 宽不出现页面横向滚动；表格在自己的容器里横向滚。站点只有深色模式。
6. **图表规则**：
   - 品类颜色固定顺序，不随筛选重新上色；
   - 两种系列（黑五/节礼日）不能只靠颜色区分；
   - 不用双 y 轴；
   - 每个图有悬停提示（SVG `<title>` 即可）。

## 7. 流程

1. 从远程分支 **`origin/data/bf2026-scraped`** 开分支 `feat/bf2026-ui-v2`。
   - 这个分支 = main + 抽查通过的 OzBargain 黑五 / 节礼日数据（约 5,000 条）。

3. 做完开 PR，目标分支 `main`，描述里写：改了什么、验收清单逐项结果、截图。**不要自己合并**——合并会自动部署上线，等人审。
